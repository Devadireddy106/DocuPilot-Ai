# DocuPilot AI — Intelligent PDF-to-Excel Agent
**From documents to trusted data.**

DocuPilot AI converts digital and scanned PDFs (up to 50 pages) into structured Excel workbooks. For every page an
explainable agent decides how to read it (native text, table detection, or OCR), checks the result, retries with a
different strategy when that is useful, and **flags what it is not sure about instead of presenting it as verified**.

Built for the INCUXAI AI Agent Development Challenge 2026. This is an independent project; it is not endorsed by or
affiliated with INCUXAI.

* 100 % free and open source: Python, Gradio, PyMuPDF, pdfplumber, Tesseract OCR, pandas, openpyxl. No API keys, no GPU, no Docker.
* Runs on a CPU-only Windows laptop; the browser (phone, tablet, laptop) only uploads and downloads — all processing is on the server running `app.py`.
* No internet needed to convert a PDF once the dependencies and the Tesseract executable are installed.

## What it does

| Capability | How |
|---|---|
| Digital PDFs | pdfplumber (ruled tables) → own geometry analysis of PyMuPDF words (un-ruled tables) |
| Scanned PDFs | Page render → grayscale/deskew/denoise/binarise + table-border removal → Tesseract → geometry analysis |
| Mixed documents | **Per-page** classification and routing (digital / mixed / scanned / unreliable text / blank) |
| 10+ columns | Tested with 12- and 16-column tables |
| Tables across pages | Conservative merge: repeated header, or header-less continuation with page-position + value-type evidence; otherwise kept separate and flagged |
| Validation | Duplicates, missing values, numeric/date parsing, ambiguous & invalid dates, outliers, misaligned columns, wrapped-text rows, source totals, low OCR confidence, failed pages |
| Honesty | Findings are *Confirmed*, *Potential* or *Unverified*; OCR output is always listed as unverified; automatic fixes are recorded; partial results are marked **PARTIAL** |
| Output | `Extracted_Data` (+ more sheets for more tables), `Validation_Report`, `Processing_Summary`, plus a CSV validation report and a JSON processing log (no cell values) |

## Quick start on Windows (PowerShell)

> These commands were prepared from standard Windows tooling but **could not be executed on Windows in the environment
> where this project was built** (it was built and tested on Linux). Please follow them once and report anything that differs.

```powershell
# 1. Extract the ZIP (adjust the path if your download is elsewhere)
Expand-Archive -Path "$HOME\Downloads\DocuPilot_AI.zip" -DestinationPath "$HOME\Documents" -Force

# 2. Open the project folder (and VS Code)
cd "$HOME\Documents\docupilot-ai"
code .

# 3. Create a virtual environment (Python 3.11 or 3.12 from python.org recommended)
py -3.12 -m venv .venv

# 4. Activate it   (if blocked:  Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass)
.\.venv\Scripts\Activate.ps1

# 5. Install the Python dependencies
python -m pip install --upgrade pip
pip install -r requirements-dev.txt

# 6. Install the Tesseract OCR *program* (the pip package pytesseract is only a wrapper for it)
winget install --id UB-Mannheim.TesseractOCR -e
#    No winget?  Download the installer from https://github.com/UB-Mannheim/tesseract/wiki and keep the default folder.
#    Verify:
& "C:\Program Files\Tesseract-OCR\tesseract.exe" --version
#    If the app still says "OCR not available", point it at the executable for this session:
$env:TESSERACT_CMD = "C:\Program Files\Tesseract-OCR\tesseract.exe"

# 7. Run the tests (records reports\test_results.json)
python scripts/run_tests.py

# 8. Run the benchmark (records reports\benchmark_results.json, .csv, .md)
python scripts/run_benchmark.py          # add --skip-ocr if Tesseract is not installed

# 9. Launch the app, then open http://127.0.0.1:7860
python app.py
```

More detail, VS Code debugging and troubleshooting: [docs/windows_setup.md](docs/windows_setup.md).

## Using it

1. Open the app, choose a PDF (tap the box, or drag-and-drop on a computer).
2. Tap **Convert to Excel**. The progress bar and stage list reflect what the backend is really doing (page *n* of *N* …).
3. Review the preview and the validation list. Rows highlighted amber/red in the workbook need a human look.
4. Download the workbook, the validation CSV and the processing log.

See [docs/user_guide.md](docs/user_guide.md).

## Evidence (real, generated by this repository's scripts)

* `reports/test_results.json|txt` — pytest outcome (passed / failed / skipped, with environment).
* `reports/benchmark_results.json`, `benchmark_cases.csv`, `benchmark_summary.md` — metrics per document and per document type.
* `samples/` — synthetic PDFs and the workbooks the pipeline **actually produced** from them (`samples/generated_outputs/`).
* [docs/accuracy_report.md](docs/accuracy_report.md) — interpretation, including the failures.

**All benchmark documents are synthetic.** They show the system works on those layouts and exposes where it breaks; they do
**not** establish accuracy on real-world documents. OCR is never perfect — OCR values are always flagged as unverified.

## Project layout

```
app.py                     Gradio web app (entry point; also used by Hugging Face Spaces)
config/settings.py         every limit and heuristic threshold, with environment overrides
src/
  pdf_preflight.py         signature, size, corrupt/encrypted, page-limit checks
  document_classifier.py   per-page kind (digital / mixed / scanned / unreliable_text / blank)
  extraction_agent.py      the per-page decision engine (plan, attempt, score, retry, decide, log)
  pdf_extractor.py         native text access, pdfplumber strategies, geometry-based table finder
  ocr_engine.py            Tesseract discovery + preprocessing + word-level OCR
  table_reconstructor.py   cross-page merging, repeated headers, page furniture, headers
  schema_normalizer.py     number/date parsing, column typing, deterministic OCR corrections
  validator.py             all validation checks (never edits values)
  excel_exporter.py        workbook writer + re-open verification + formula-injection defence
  processing_report.py     summary rows, CSV/JSON reports, UI text
  pipeline.py              PDF in → workbook + reports out
  file_manager.py          safe temp workspaces, filename sanitising, output housekeeping
  models.py                dataclasses shared by every stage
tests/                     pytest suite + synthetic fixture factory + benchmark library
scripts/                   run_tests.py, run_benchmark.py
docs/                      architecture, user guide, demo script, accuracy report, deployment, limits, checklist
samples/                   synthetic sample PDFs + generated workbooks (see samples/README.md)
```

## Privacy

Uploaded PDFs are untrusted input and are processed locally by whichever machine runs `app.py` (your laptop, or the
hosting server if you deploy it). Nothing is sent to third-party services. On a hosted deployment the file *is* uploaded to
that server; see [docs/deployment.md](docs/deployment.md) for what is and is not guaranteed about retention.
The app deletes its own private working copy after each conversion and removes its own generated outputs older than
24 h (`DOCUPILOT_RETENTION_HOURS`) on the next run; the hosting platform may keep separate upload caches or logs.

## Known limitations (short list — full list in [docs/known_limitations.md](docs/known_limitations.md))

* Wrapped cell text in **un-ruled** tables is read as extra rows (flagged, not merged).
* Very poor scans are rejected as failed pages rather than guessed (OCR mean confidence < 35/100).
* Tested only on synthetic documents, on Linux, with Python 3.13 and Tesseract 5.3.4. Windows, other Python versions, other browsers/devices and real-world documents are **not** tested.
* Only English OCR (`eng`) is configured.
